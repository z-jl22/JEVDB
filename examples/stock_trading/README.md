# JEVDB 股票新闻模拟交易示例

这是一个**仅供课程演示的模拟交易**程序，不连接券商，也不发送真实订单。示例数据使用真实的五粮液（`000858`）和中国平安（`601318`）公告及历史行情；模型判断、订单和收益均为模拟结果。

## 示例数据与来源

- `prices.csv`：两只 A 股在 2025-04-24 至 2025-05-15 的 13 个交易日开盘价、最高价、最低价、收盘价（元/股）和成交量（手，每手 100 股），共 26 行，取自东方财富日线接口，参数 `klt=101&fqt=0` 表示日线、未复权：[五粮液行情](https://push2his.eastmoney.com/api/qt/stock/kline/get?secid=0.000858&klt=101&fqt=0&beg=20250424&end=20250515&fields1=f1,f2,f3,f4,f5,f6&fields2=f51,f52,f53,f54,f55,f56)、[中国平安行情](https://push2his.eastmoney.com/api/qt/stock/kline/get?secid=1.601318&klt=101&fqt=0&beg=20250424&end=20250515&fields1=f1,f2,f3,f4,f5,f6&fields2=f51,f52,f53,f54,f55,f56)。只选取接口返回的日期、OHLC 和成交量字段。
- `trading_rules.csv`：每只股票的交易参数，均为**可调整的模拟假设**，不是行情源提供的历史逐笔费率。样本设置买入 100 股整手、卖出 1 股单位、最小报价单位 0.01 元；佣金按成交额 0.03% 且每单最低 5 元，过户费双边 0.001%，印花税仅卖出 0.05%，滑点 0.05%，涨跌幅限制 10%，单笔成交不超过当日成交量的 1%。具体券商佣金、交易规则和适用税费可能因证券、市场及日期而异，应按实际实验设定核对并修改。
- `news.csv`：两条新闻是对 2025-04-26 公告中财务事实的简短改写，不是新闻原文。[五粮液一季度报告](https://static.cninfo.com.cn/finalpage/2025-04-26/1223311586.PDF)与[中国平安一季度报告](https://paper.cnstock.com/html/2025-04/26/content_2056672.htm)分别支持各行事实；`source_url` 记录原始出处，交易程序不会将该列发送给模型。

公告只核实到**披露日期**，没有可靠的具体发布时间。`published_at` 的 `T00:00:00` 是适配现有 CSV 格式的日期占位，**并非真实发布时间**。程序无论该占位时间为何，都只会在披露日期之后的首个交易日（本例为 2025-04-28）开盘执行信号。真实价格和真实公告不代表交易策略有效；本样本很小，主要用于验证“需求→JEVDB 分类→模拟交易→结果展示”的流程。数据仅作课程小样本使用，进一步传播请核对来源网站条款。

## 运行

在已安装 JEVDB 的 `jevdb` Conda 环境、仓库根目录运行：

```sh
conda activate jevdb
python examples/stock_trading/trade.py
```

不带参数时进入交互式实验台：选择股票、日期、资金和模型服务，先查看新闻及交易参数，再决定何时调用 JEVDB。分类结束后可查看每条新闻的摘要、原始来源和模型标签，再确认开始模拟。结果菜单可查看订单、每日资产、文件位置，也可修改资金、佣金率或滑点率后重跑；重跑仅重新计算交易，不重复调用模型。输入 `0` 退出。还可以带 `--interactive` 显式进入交互模式，并通过 `--prices`、`--news`、`--rules`、`--output` 指定文件。

“可选股票”从 `prices.csv` 的 `name` 列读取中文名称，显示为 `000858（五粮液）`。选择股票后会显示它们共同拥有行情的日期范围；开始、结束日期提示也会标明边界。若区间没有新闻或行情不完整，会说明原因并让用户重新选择日期。

结果菜单中选择 `5 开始新一轮`，可重新选择股票、日期、资金和模型。同一次程序运行可以完成多轮独立实验，每轮从空仓和指定初始资金开始；相同新闻和模型可复用缓存。选择 `3` 则只修改资金、佣金率和滑点后重跑当前区间。每次模拟结果分别保存在 `--output/run_日期_时间_标识/`，可保留并比较多轮结果，分类缓存保存在 `--output/decision_cache.json`。

如需无人值守地批量运行，三个参数须同时提供：

```sh
python examples/stock_trading/trade.py --symbols 000858,601318 --start 2025-04-24 --end 2025-05-15
```

默认使用 `reviews.py` 中注释的 OpenAI 兼容配置：`jevdb_backend='llm'`、endpoint `https://open.bigmodel.cn/api/coding/paas/v4`、模型 `glm-5.3`。运行时会隐藏输入的 `OPENAI_API_KEY`；也可以提前在环境变量中设置。这里的环境变量名沿用 JEVDB 对 OpenAI **兼容**后端的约定，并不表示服务商是 OpenAI。所选服务必须支持 Chat Completions 严格 JSON Schema 输出；该组合的实际兼容性需要通过首次调用验证。

如果要沿用 `reviews.py` **当前启用**的 Jev 配置，增加 `--backend jev`：

```sh
python examples/stock_trading/trade.py --backend jev --symbols 000858,601318 --start 2025-04-24 --end 2025-05-15
```

这会使用 endpoint `https://app.vllm-sr.ai/v1`、模型 `vllm-sr/d3-ultra`，并读取 `JEV_API_KEY`。两种后端均可通过 `--model`、`--endpoint` 覆盖默认值。运行会向所选服务发送新闻标题、正文和股票代码，可能产生 API 费用。交互模式中的“重新调用模型”会绕过分类缓存，可能再次计费。没有真实模型结果时，程序不会把预置标签冒充 JEVDB 判断。

## 从需求到结果

1. 用户通过 `--symbols`、`--start`、`--end`、`--capital` 指定股票池、日期和初始资金；`--prices`、`--news`、`--rules` 可以换成自己的 CSV 文件。
2. 程序连接 JEVDB，调用 `jev_choose` 将每条新闻分类为 `positive`、`negative`、`neutral`。查询条件只要求判断对公司业务的可能影响，不预测股价。分类结果按后端、服务地址、模型、条件、文本内容缓存到 `--output` 下的 `decision_cache.json`，重复运行可复用；新闻或模型变化则重新判断。
3. 新闻发布日**之后**的第一个有行情的交易日开盘执行信号：同日同股票新闻全为正面时买入，全为负面时卖出；有中性或冲突时不交易。超出回测区间、或区间内没有下一交易日的新闻不形成订单。
4. 模拟引擎逐日更新现金和持仓，并在终端展示新闻判断、订单执行、期末资产、收益率和最大回撤。导出 `decisions.csv`、`orders.csv`、`equity.csv` 和 `experiment.json`；订单明细包含佣金、过户费、印花税和跳过原因，JSON 记录本次模型、参数与分类结果。交互模式为每次模拟建立独立结果目录；批量模式仍直接写入 `--output`，重复使用同一目录时会覆盖批量结果。

## 交易假设与边界

- 按 A 股日线的简化规则：买入数量按 `buy_lot` 取整，卖出按 `sell_lot` 取整；同日买入的股份不能同日卖出（T+1）。同日订单先处理卖出，再处理买入；不允许卖空。
- 成交候选价为开盘价加减 `slippage_rate`，再按 `tick_size` 四舍五入。若候选价不在当日最低价与最高价之间，就跳过；以前一交易日收盘价计算涨跌停价，开盘已触及买入涨停或卖出跌停时保守地跳过，相应候选价超出涨跌停价也跳过。此规则仍无法从日线判断盘口是否有足量可成交委托。
- 交易费用按每笔成交计算：双边佣金 `max(成交额 × commission_rate, min_commission)`、双边过户费 `成交额 × transfer_fee_rate`，卖出另收 `成交额 × stamp_duty_rate`；每项四舍五入到分。资金、单只股票占开盘资产 20% 的上限、`volume_lots × 100 × max_participation_rate` 同时约束成交数量；买入不足一手则跳过。参与率是日成交量的粗略限制，日线无法证明开盘时可成交相同数量。
- 每日以收盘价计算总资产。没有融资、股息、除权处理、停牌和真实订单簿；若新增复权行情、除权日、ST 或其他涨跌幅规则，须同步校正对应的交易参数和前收盘价口径。行情缺失时报错。
- `jev_choose` 是模型判断，可能出错或随模型变化。模拟收益不构成投资建议，也不能证明策略有预测能力。若扩展为严格历史回测，必须逐条核实新闻的实际发布时间、当时可获得性和行情口径。

输入 CSV 必需列：行情为 `date,symbol,open,high,low,close,volume_lots`；新闻为 `news_id,symbol,published_at,title,body`，可附加 `source_url` 等来源列；参数表为 `symbol,buy_lot,sell_lot,tick_size,commission_rate,min_commission,transfer_fee_rate,stamp_duty_rate,slippage_rate,price_limit_rate,max_participation_rate`。费率均用小数表示，例如 `0.0005` 表示 0.05%。日期格式为 `YYYY-MM-DD`，发布时间为不带时区的本地时间 `YYYY-MM-DDTHH:MM:SS`。三张表的股票代码需一致；每个回测交易日都要有选中股票的完整 OHLC 和成交量。用 Excel 打开 CSV 时，请将 `symbol` 列按文本导入，以保留 `000858` 的前导零。

三个输入 CSV 文件开头都用 `#` 行解释各列。`trade.py` 读取时会跳过这些注释行；如果用 Excel、DuckDB 或其他标准 CSV 工具直接导入，应先跳过开头的注释行，或将它们删除后再导入。

## 组件与权限

| 组件 | 输入与输出 | 依赖、权限及检查点 |
|---|---|---|
| JEVDB（仓库 `LICENSE` 为 MIT） | 新闻文本 → 分类标签 | 通过 DuckDB 扩展调用模型；需要读取本地输入、访问指定模型服务；判断可能出错，应人工核验样本。 |
| OpenAI 兼容或 Jev 模型服务 | 分类任务与新闻文本 → 结构化答案 | 分别需要 `OPENAI_API_KEY` 或 `JEV_API_KEY` 和网络；服务会接收新闻文本并可能计费。更换服务时核对其条款和数据处理方式。 |
| Python 标准库 CSV 与模拟账本 | 行情、标签、初始资金 → 订单和资产曲线 | 仅写入 `--output` 指定的本地目录；不连接真实交易账户。 |

本示例没有引入额外的第三方 Skill。若课程报告要求调研开源 Skills，可以把候选的数据获取或回测工具单独评估其来源、许可证、权限，再决定是否集成；不要将其描述为 JEVDB 原生调用的能力。
